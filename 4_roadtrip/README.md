# 雨季旧公路

一个本地运行的文字公路冒险，Node.js + TypeScript 后端与浏览器界面。沿雾桥驿、回声坡、海角镇旅行，和居民聊天、调查物件、介入事件、跳过支线或返回旧地，最后把真实经历写成尾声。

## 启动

需要 **Node.js 24 或更新版本**。这个版本没有第三方运行依赖，不需要安装 Python 包或先建向量库。

在项目根目录运行：

```powershell
cd 4_roadtrip
npm start
```

PowerShell 若限制执行 `npm.ps1`，使用 `npm.cmd start`。

浏览器打开 [雨季旧公路](http://127.0.0.1:4317)。服务默认仅绑定本机，关掉终端即停止。重新启动会恢复当前存档。端口占用时，可在 PowerShell 设置 `$env:PORT="4318"` 后再启动。

## 两种运行方式

- **离线示例**：首次启动的默认方式，无需 Ollama 就能玩完三站。人物和对白由预设与规则提供，界面明确标记“非 AI”。
- **Ollama**：打开右上角设置，填写地址和模型，点“测试连接”，再保存。可填写远程地址 `http://172.30.234.17:11434`，前提是两台电脑能互通，Ollama 监听该网卡并允许端口访问。前端不直接请求 Ollama，由 Node 后端转发。

更改示例/AI方式后需要新建旅程；同一段旅程不混入另一种来源的内容。模型和超时可在同一 AI 旅程中调整。测试连接只读取模型列表与已加载模型信息，不启动生成。

AI 模式会在首次到达地区时生成氛围、人物姓名与来历、性格、说话方式，并生成自由对话。三站地点、角色职能、事件核心事实与结束条件由程序预设，让短途旅程先保持因果一致；当前还不是任意世界下的无限动态事件系统。收信人姓名固定为林澜。

建议先使用4096上下文试运行。6GB显存设备使用7B/8B模型可能发生部分CPU计算；Node只负责交互，不会改善模型推理本身。以实际运行时的 `ollama ps`、显存占用和响应时间为准。

## 怎么玩

1. 点“发动引擎”进入雾桥驿，选择人物并自由输入对话。
2. 调查当地两件物品。确认信息后，会出现一个明确的介入操作。
3. 可以介入，也可以直接上路；不需要做完事件才能移动。
4. 左边路线可以返回已访问地区。旧人物、线索和事件结果会保留。
5. 抵达海角镇后可选择结束。未送出的信不会被尾声假装送达。

自由输入当前用于人物交谈；改变事件、调查与旅行使用界面按钮，避免模型随口修改世界。首版每个地区有一个可介入结果，尚不支持任意自由行动或多种事件解决办法。模型可能拒绝、不合角色或产生矛盾，仍需要真实游玩调优。

生成中的对白会逐步显示，地区JSON和人物隐藏背景不发送给前端。取消和错误不提交未完成行动；若取消恰好发生在保存完成之后，页面会重新读取实际存档。

## 世界观与存档

[阅读示例世界观](presets/世界观.md)。运行时预设在 `presets/world.ts`；新建旅程可填写语气或体验补充，仍遵守这个世界的核心规则。

本地状态放在 `data/`：

- `journey.json`：当前旅程。
- `settings.json`：个人模型地址、模型名与参数。
- `*.json.bak`：上次有效保存的备份；主文件损坏时尝试恢复。

新建旅程替换当前进度，不是多存档槽；只保留上一版本备份。请勿把备份当成长期归档。`data/`、`logs/`、`node_modules/`、构建产物与本地环境变量都已忽略，不纳入 Git。Git只保存源码、预设、测试与说明。

## 验证

```powershell
npm test
npm run check
```

测试覆盖三站通关、跳过支线、回访、私有背景隔离、人物对话记忆隔离、重复/过期请求、取消、模型失败、备份恢复，以及模拟Ollama HTTP接口的分块流式协议。

`npm run check` 使用 Node 原生 TypeScript 类型擦除和 JavaScript 语法检查，不等同于完整 `tsc` 类型检查。本版使用可擦除的TypeScript语法，服务启动时将前端TS转换为浏览器JS，无需打包或额外依赖。

2026年10月23日，已使用远程 Ollama 的 `qwen2.5:7b`、4096上下文，实际生成三站、完成一次人物对话并通关。一次热模型复测中地区生成约9至11秒、对话约2秒；这些是单次观察，不是性能保证。浏览器也已验证离线三站通关、设置保存、刷新恢复和完结回看。

实测曾出现人物身份混淆和多人剧本式回答。当前已明确玩家身份与居民关系，并对明显多说话人标签或代写玩家段落重试一次。模型仍可能有更隐蔽的语义矛盾，不能用格式校验替代人工判断。
